1. Giới thiệu

1.1. Mục đích báo cáo

Báo cáo này trình bày kết quả kiểm thử hệ thống WowFood sau giai đoạn kiểm thử chức năng, bảo mật, hiệu năng, đơn vị và tích hợp. Tài liệu bổ sung cho Kế hoạch kiểm thử (BAO_CAO_KIEM_THU.md) và bộ test case (TEST_CASE_WOWFOOD.xlsx, KIEM_THU_KHAC.md).

1.2. Đối tượng kiểm thử

Ứng dụng Web PHP đặt món ăn trực tuyến gồm: giao diện khách hàng, panel quản trị, REST-like API JSON, tích hợp VNPay, MoMo, GHN và gửi email (PHPMailer).

1.3. Tài liệu tham chiếu

  • Kế hoạch kiểm thử WowFood v1.0
  • Đặc tả yêu cầu / Thiết kế hệ thống (pttkht_wowfood.md)
  • OWASP Top 10 — hướng dẫn kiểm thử bảo mật Web
  • Tài liệu tích hợp VNPay Sandbox, MoMo Test, GHN Dev API

2. Phạm vi và môi trường kiểm thử

2.1. Phạm vi

Kiểm thử trong phạm vi: đăng ký/đăng nhập, duyệt menu, giỏ hàng, đặt hàng, thanh toán (COD/VNPay/MoMo), voucher, GHN, chat, hoàn tiền, quản trị admin; kiểm thử bảo mật (xác thực, phân quyền, SQLi, IDOR, API session); hiệu năng cơ bản; tích hợp end-to-end.

Ngoài phạm vi: kiểm thử hạ tầng production, load test quy mô enterprise (>500 user đồng thời trên môi trường thật), kiểm thử phía cổng thanh toán của bên thứ ba.

10. Đánh giá và kết luận

10.1. Đánh giá chung

Hệ thống WowFood v1.0 đáp ứng các yêu cầu chức năng cốt lõi của đồ án: đặt món, thanh toán, quản trị, tích hợp bên thứ ba ở mức sandbox. Cơ chế bảo mật cơ bản (hash mật khẩu user, prepared statement, phân quyền admin/user, chữ ký VNPay/MoMo, chống IDOR đơn hàng) hoạt động đúng. Tồn tại các điểm cần cải thiện trước production: CSRF, rate-limit login, loại bỏ plaintext admin login, tối ưu truy vấn lịch sử đơn.

10.2. Tiêu chí đầu ra (Exit Criteria)

TC P1 PassĐạt (> 95% test P1 Pass hoặc có workaround)
Lỗi Critical/High mở1 High (CSRF) — cần xử lý trước release
UAT / Sign-offĐề xuất chấp thuận có điều kiện cho môi trường đồ án/demo

10.3. Khuyến nghị

  • Bổ sung CSRF token cho mọi form POST và API state-changing.
  • Bỏ so sánh mật khẩu plaintext tại admin/login.php; migrate hash toàn bộ admin.
  • Thêm rate-limit đăng nhập (session hoặc DB lockout).
  • Index DB cho tbl_order (user_id, order_date); phân trang order-history.
  • Triển khai staging HTTPS + test lại MoMo IPN và session timeout.
  • Tách helper (voucher, payment sign) và bổ sung PHPUnit trong thư mục tests/.
